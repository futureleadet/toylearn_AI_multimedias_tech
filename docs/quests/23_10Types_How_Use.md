## 가상 문제 상황
1. 가상 문제 상황 (Scenario Challenge)
페르소나 (Persona):
직무: 헬스케어 스타트업 '웰니스 핏(Wellness Fit)'의 주니어 PM (Product Manager)
성향: 아이디어는 많지만, 이를 개발자나 디자이너가 이해할 수 있는 기술적 언어로 정리하는 데 어려움을 겪고 있음.

배경 (Background):
당신은 개인 맞춤형 영양 관리 웹 서비스인 '뉴트리 가이드(Nutri-Guide)'의 MVP(최소 기능 제품) 웹 프로토타입을 기획 중입니다.
일주일 뒤, 개발팀 및 디자인팀과 함께 '프로토타입 제작 킥오프 미팅'이 예정되어 있습니다.
현재는 "사용자가 식단을 입력하면 칼로리를 계산해준다", "깔끔한 대시보드가 있었으면 좋겠다" 정도의 추상적인 아이디어만 나열된 상태입니다.

핵심 문제 (Problem):
개발 리더로부터 **"기능 명세가 너무 모호해서 DB 설계나 프론트엔드 구조를 잡을 수 없다"**는 피드백을 받았습니다.
구체적인 필수 기능 리스트(Feature List), 사용자 흐름(User Flow), 데이터 요구사항이 정의되지 않으면 프로젝트 착수가 무기한 연기될 위기입니다.

해결 과제 (Task):
추상적인 아이디어를 개발자와 디자이너가 즉시 작업할 수 있는 수준의 **'웹 프로토타입 제작을 위한 상세 요구사항 리스트'**로 변환해야 합니다.
기능적 요구사항(회원가입, 식단 입력, 리포트 출력 등)과 비기능적 요구사항(보안, 로딩 속도 등), 그리고 필요한 페이지 구조를 빠짐없이 도출해내야 합니다.

## 문제 해결 프롬프트 


페르소나 (Persona): 너는 10년차 앱개발 업체 프로덕트 매니저야

배경:
당신은 개인 맞춤형 영양 관리 웹 서비스인 '뉴트리 가이드(Nutri-Guide)'의 MVP(최소 기능 제품) 웹 프로토타입을 기획 중입니다.
일주일 뒤, 개발팀 및 디자인팀과 함께 '프로토타입 제작 킥오프 미팅'이 예정되어 있습니다. 고객사 는 현재 "사용자가 식단을 입력하면 칼로리를 계산해준다", "깔끔한 대시보드가 있었으면 좋겠다" 정도의 추상적인 요구사항만 제시.

요구사항정리:
- 타켓 : 20대 여성으로 건강 및 다이어트에 관심이 많은 사람 
- 디자인 컨셉은 귀여움과 분홍핑크
- 목표 : 앱에 자신의 식단 및 라이프스타일을 기록하고 SNS 통해 공유하여 앱에서 전문 관리를 받고 지인들에게도 자신에 대한 피드백을 받아 관리
- 주요기능
1. 식단 사진만 찍어도 식단 리스트 및 칼로리 자동 입력 및 피드백
2. SNS 연동 및 피드백 기능
3. 경고 : 특정 칼로리 이상 넘었을 경우, 특정 시간 식단을 올리지 않았을 경우, 
4. 칭찬 기능 : 관리를 더욱 잘 하기 위해 특정 목표 달성시 뱃지 기능
5. 히스토리 분석 기능 : 저장된 데이터를 도대로 그래프 등 목표 달성 현황 등을 일자별로 관리
6. 최종 목표 아바타 : 현재 데이터를 통해 목표하는 아바타(목표 사진)이 어떻게 변할지를 예측하는 기능
- 개발환경
1. iOS만 개발 (안드로이드 추후 개발)
2. 앱과 웹 동시 진행하나 기능적으론 큰 차이없음
3. 개인화 : 개인에 따른 첫화면 변화


출력사항
- 앱 광고 홍보를 위한 마케팅 가이트 스크립트
- 웹 프로토타입 제작을 위한 기능 요구서
- 대표 앱 첫화면 디자인

### 2. 📑 웹 프로토타입 제작을 위한 기능 요구서 (FRD) - MVP

> **[PM 코멘트]**
> * 요구사항에 명시된 6가지 주요 기능(AI, SNS, 경고, 칭찬, 히스토리, 아바타)을 MVP(최소 기능 제품) 단계에서 모두 완벽하게 구현하는 것은 불가능하며, 그래서도 안 됩니다.*
> * *이번 MVP의 핵심 목표는 **"사용자가 식단 기록(1)과 현황 파악(5)이라는 핵심 가치를 경험하고, 이에 대한 동기부여(4)와 재미(2)를 느끼게 하는 것"**입니다.*
> * *AI(1)와 아바타(6) 기능은 MVP에서 기술적 난이도가 가장 높습니다. AI는 핵심이지만 초기엔 '사진 인식 후 유저가 확인/수정'하는 수준으로, 아바타는 'Future Scope'로 정의합니다.*
> * *본 문서는 웹 프로토타입(반응형) 기준이며, iOS 네이티브 앱 개발 시 병행 참고합니다.*

#### 1. 프로젝트 개요

* **프로젝트명:** 뉴트리 가이드 (Nutri-Guide) MVP
* **목표:** 20대 여성을 타겟으로 한 개인 맞춤형 영양 관리 웹 서비스의 핵심 가설 검증 (식단 기록의 용이성 및 SNS 공유를 통한 동기부여 효과)
* **타겟 디바이스:** 반응형 웹 (모바일(iOS) 브라우저 최우선)
* **디자인 컨셉:** Cute & Pink. 사용자에게 친근하고 동기를 부여하는 UX/UI.

#### 2. MVP 기능 범위 (Scope)

| 기능 분류 | In-Scope (MVP 구현) | Out-Scope (Future Scope) |
| :--- | :--- | :--- |
| **G-01: 회원 및 프로필** | * 소셜 로그인 (카카오/네이버)
* 닉네임, 키, 현재 체중, 목표 체중 입력 | * 일반 이메일 회원가입/로그인
* 상세 프로필 (알레르기, 선호 음식 등) |
| **G-02: 식단 기록 (Feature 1)** | * **AI 사진 인식 (핵심):** 사진 업로드 시 음식명 리스트 *제안*. (유저가 리스트 확인 및 수정)
* 음식명 기반 칼로리 자동 계산 (DB 매칭)
* 수동 입력 (음식 검색 및 직접 입력) | * 완벽한 100% 자동 AI 분석 및 피드백
* 영상 기반 식단 분석 |
| **G-03: SNS 및 공유 (Feature 2)** | * '내 기록'을 이미지 카드로 생성 (인스타그램 공유 연동)
* 앱 내 '친구 피드' (서로 팔로우한 지인들의 기록 확인)
* '좋아요' 및 간단한 이모티콘 피드백 기능 | * 앱 내 상세 댓글 기능
* 타 SNS(트위터, 페이스북) 연동
* '전문가' 피드백 기능 (운영 코스트) |
| **G-04: 동기부여 (Feature 4)** | * **칭찬 뱃지:** 특정 목표 달성 시 뱃지 지급 (예: 3일 연속 기록, 첫 주 목표 달성)
* 'My 뱃지' 페이지 (수집 현황) | * 랭킹 시스템
* 포인트 및 리워드 시스템 |
| **G-05: 히스토리 분석 (Feature 5)** | * **대시보드 (핵심):** 오늘 섭취 칼로리/권장 칼로리 (도넛 그래프), 최근 7일 섭취 칼로리 (라인 그래프)
* '기록' 탭: 일자별(캘린더 뷰), 식단별(아침/점심/저녁) 기록 리스트 | * 영양소(탄/단/지) 상세 분석
* 주간/월간 상세 리포트 PDF 다운로드 |
| **G-Complete** (기타) | * 개인화 홈 (Feature 3): 홈 화면에 유저 닉네임 및 뱃지 현황 노출 (간단한 수준) | * 경고/알림 (Feature 3): MVP 범위 제외 (푸시 알림은 웹에서 구현이 까다롭고 유저 피로도 증가 우려)
* 아바타 예측 (Feature 6): 기술 난이도 최상. MVP 이후 핵심 기능으로 개발. |

### 3. 🎨 대표 앱 첫 화면 (홈) 디자인 컨셉 (시안)

> **[PM 코멘트]**
> * *고객사의 '깔끔한 대시보드'와 우리의 '개인화 첫 화면' 요구사항을 결합해야 합니다.*
> * *20대 여성이 매일 접속하고 싶은, '귀엽고 직관적인' 대시보드가 컨셉입니다.*
> * *디자인팀은 메인 컬러 (베이비 핑크 #FFC0CB, 화이트)와 포인트 컬러 (코랄 핑크 #F8AFA6)를 활용하여 시안을 구체화해 주세요.*

#### 홈 화면 레이아웃 (위젯 기반 대시보드)

**(1) 헤더 (Header)**
* `"지수님, 오늘도 파이팅! 💖"` (Feature 3: 개인화)
* 오른쪽 상단: 알림 아이콘, 설정 아이콘

**(2) 메인 대시보드 (오늘의 현황) - (Feature 5)**
* 가장 상단에 위치.
* "오늘 섭취한 칼로리"
* **[ 귀여운 도넛 모양 그래프 ]** (중앙에 "1250 / 2000 kcal" 표시)

* 화면 우측 하단에 **[ 핑크색 카메라 아이콘 FAB(플로팅 버튼) ]** (Feature 1)

* "My 뱃지 현황 🏆"

* "친구들은 지금 🥗"
